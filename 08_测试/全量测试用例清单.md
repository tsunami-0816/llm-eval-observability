# 全量测试用例清单（第 8 步 · R1）

> 框架：`08_测试/qa-automation/`（pytest 四层金字塔），一键运行 `python -m pytest --tb=short -q`。
> R1 结果：**62 passed / 1 xfailed / 0 failed（18.2s）**。P0 冒烟子集见 `qa-automation/data/p0_cases.json`。

## 分层分布（共 63 条）

| 层 | 条数 | 占比 | 说明 |
|---|---|---|---|
| L1 单元 | 26 | 41% | 纯函数/工具类，外部依赖全 mock |
| L2 接口集成 | 28 | 44% | 真实 HTTP 打 8086 后端，每接口四象限 |
| L3 中间件集成 | 3 | 5% | **降级**：直连 docker-compose 中间件（未用 testcontainers，原因见下） |
| L4 E2E | 3 | 5% | 仅 P0 主路径 |

> **L3 降级原因**：本机 16G 内存，docker-compose 三容器（MySQL/ClickHouse/Redis）常驻已占资源，testcontainers 再开临时容器有 OOM 与启动过慢风险。按 8.0 允许降级为「L2 接口 + 直连已起中间件对账」，在此显式说明。
> **占比说明**：L2 偏重是因本项目核心交付是 15 个 API 端点；L3/L4 按「少而精」定位合计 9.5%，覆盖双写对账/缓存/主链路。
