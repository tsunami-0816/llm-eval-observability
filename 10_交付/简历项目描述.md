## 一、八段式（自用详版）

### A 一句话（38 字）

LLM 应用评测与可观测平台：FastAPI + ClickHouse + Vue3，11 个接口、7 张表。

### S 背景

LLM 应用上线后，调用成本、延迟、错误率和 Prompt 改版效果散落在各业务日志里，改动 Prompt 无法量化好坏。约束：单人开发、本机 RTX 2050 4G 显存 / 16G 内存、**无真实 LLM API key**，因此只做 3 容器单机部署，评测判官用 Mock。

### T 目标（只写实测达成情况）

| 目标（第 1 步基线） | 实测 |
|---|---|
| 上报 ≥100 QPS 且不丢数据，成功率 ≥99.9% | **545.7 QPS，158180 条请求与入库 158180 条对账一致，HTTP 错误率 0%**（超额达成） |
| 100 万条明细聚合 P95 ≤ 1s | **P95 = 63.3ms，avg 51.6ms**（达成） |
| 上报故障时业务劣化 ≤ 5ms | **0.926ms/次**（达成） |
| 看板首屏 ≤ 2s | **654.5ms；接口 P95 50.0ms**（达成） |
| 100 case 评测 ≤ 60s（Mock 判官） | **0.3s**（达成，但为 Mock） |
| 入库 token/成本与真实 API usage 误差 ≤1% | **未验证**（无真实 key，token 为「字符数/4」估算） |

### A 动作（做了什么 → 为什么 → 落在哪个模块）

1. **明细与配置双存分离** → 百万级聚合走列存、事务性配置留 MySQL → `traces.py` / `clickhouse_client.py` / `models.py`（6 张 MySQL 业务表 + 1 张 CH `trace_records`）。
2. **SDK 装饰器 + patch `Completions.create` 自动埋点，上报 fire-and-forget** → 既不侵入业务代码，也不能让上报拖慢业务（M8）→ `llm_eval_sdk/openai_hook.py`、`reporter.py`。
3. **同步 ClickHouse 写入改 `asyncio.to_thread`** → 大批量 insert 不占事件循环，避免跑批期间全站 API 卡顿 → `runs.py` / `traces.py`。
4. **路由级统一 X-API-Key 鉴权，默认 fail-closed** → 原先只有上报接口校验，管理面裸奔（渗透实测无 key 可读全部数据）→ `app/auth.py`、`main.py` 依赖注入、前端 `client.ts` 拦截器。
5. **接口契约机器校验** → 实时导出 `openapi.json` + 扫描前端调用，防「前端调了后端没有的接口」→ `scripts/api_contract_validator.py`，11/11 命中、0 臆造。
6. **依赖 CVE 升级** → pip-audit（OSV 源）扫出 starlette 7 条 / aiohttp 1 条 → `requirements.txt` pin 到修复版。

### R 结果（全部实测）

- 规模：**11 个接口路径 / 7 张表**（6 MySQL + 1 ClickHouse）。
- 质量：pytest **63 用例：62 passed / 1 xfailed / 0 failed**；P0 0 条，**P1 5 条全部修复并回归 verified**。
- 性能：**545.7 QPS 零错误**、对账 158180==158180；百万条聚合 **P95 63.3ms**；首屏 **654.5ms**；上报故障劣化 **0.926ms**。
- 安全：渗透探针 **15/15**（无 key 全 401、SQLi/XSS 全拦截），pip-audit **0 漏洞**。
- 未验证：**M6 真实 LLM usage 成本对账**（无 key）、**Chrome 浏览器**未覆盖（本机未安装）。

### D 可演示点（均来自第 9 步验收清单实测通过项）

1. **SDK 接入 → trace 上报 → ClickHouse 落库 → 详情回读**（验收 A1，L4 E2E 3 条全过）。
2. **创建 run → 异步评测 → done → MySQL/CH 双写对账**（验收 A4，6:4 Mock 判官，双写一致）。

### E 诚实边界（主动写明，避免被追问穿帮）

- **评测判官与生成全是 Mock**：`_mock_llm_call` 是字符串替换、`_mock_judge` 是 6:4 硬编码，代码里有 `# MOCK` 标注；没有真实 LLM key，所以「评测准确率」类结论**不存在**，只有链路和性能数据。
- **token/成本是估算**：SDK 用「字符数/4」估 token，不是 API 返回的真实 usage → M6 成本准确性**未验证**。
- **单租户、无权限模型**：一个 key 能读所有项目数据（改 `project_id` 可横向读，实测 200），HTTPS / `hmac.compare_digest` / 项目级授权都在下版本。
- **deferred（已知未做）**：`/docs` 与 `/openapi.json` 默认开启（Q-012）、请求体集合无大小上限与分页（Q-013）、本地 compose 绑 0.0.0.0 / Redis 无密码 / MySQL 弱密码（Q-014）、前端 `npm run build` 的 vue-tsc 缺 tsconfig（Q-016）、timeseries 的 metric 参数被写死（Q-006）、Dashboard 错误率浮点未截断（Q-005）、prompt (name,version) 无唯一约束（Q-003）。
- **骨架部分**：后端无 Dockerfile（compose 的 build 上下文未补），前端无 Mock 层（`VITE_USE_MOCK` 未实现）。
- **未验证**：真实 LLM usage 对账、Chrome 浏览器。
- 单人开发 + AI 协作推进，**不是团队项目**，没有"主导/负责整个团队"这类角色。
