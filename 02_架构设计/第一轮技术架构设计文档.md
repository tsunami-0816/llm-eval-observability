## 3. 核心业务链路（端到端）

### 3.1 SDK 上报 trace（对应 M1/M2/M6/M8）

```
业务进程                          FastAPI (8086)              ClickHouse / MySQL
────────                          ──────────────              ───────────────────
openai.chat.create()
  ↓
SDK hook 拦截请求
  ↓ (计时 t0)
业务真实 LLM 调用 → 记录 t1、usage
  ↓
构造 TraceRecord{
  trace_id, project_id, model,
  prompt, output, tokens,
  cost, latency_ms, source
}
  ↓  aiohttp 异步 POST /api/traces
                              → 鉴权(project_id 白名单)
                              → 校验 Pydantic
                              → 推入内存 asyncio.Queue
                              → 立即返回 202
                              ↓
                              后台 flush 协程：
                              攒 200 条 或 500ms
                              → 批量 insert ClickHouse
                              → 失败重试 1 次后丢弃(M8)
```

- 上报失败时 SDK 端 catch 所有异常，业务调用不感知（M8 验证点）。
- 批量写入是 M2（100 QPS）的关键：单条 insert 改 batch insert。

### 3.2 Prompt 版本 A/B 对比（对应 C2/C6）

```
用户在前端建 eval_dataset → 录入 N 个 case
  ↓
选两个 prompt_version (A/B)
  ↓
POST /api/runs { dataset_id, prompt_a_id, prompt_b_id }
  ↓
BackgroundTasks 启动：
  for case in cases:
    output_a = 调被测 Prompt A (按 prompt_version.content 模板填 case.input)
    output_b = 调被测 Prompt B
    judge = LLM-as-judge 对比 A/B 哪个更好 (DeepSeek API)
    落 eval_result{ case_id, score_a, score_b, judge_reason }
  ↓
聚合 total_score_a / total_score_b → eval_run
  ↓
前端对比页渲染：分差 + 每 case judge 理由
```

### 3.3 看板聚合查询（对应 M3/M7）

```
前端 5s 轮询 GET /api/metrics/summary?range=7d
  ↓
FastAPI 查 ClickHouse：
  SELECT
    count() AS calls,
    sum(total_tokens) AS tokens,
    sum(cost_usd) AS cost,
    quantile(0.5)(latency_ms) AS p50,
    quantile(0.99)(latency_ms) AS p99,
    countIf(status='error')/count() AS error_rate
  FROM trace_records
  WHERE created_time >= now() - INTERVAL 7 DAY
  GROUP BY toDate(created_time)
  ↓
ECharts 折线渲染
```

- M3（100 万条 ≤1s）靠 ClickHouse 列式 + 按天分区 + 不建二级索引。
- M7（首屏 2s）靠 Redis 缓存聚合结果 30s，第二次请求直接命中。

## 4. 数据模型设计

### 4.1 MySQL（db = `eoe`，共用 3310）

```sql
-- 项目（MVP 单项目，但表结构预留多项目）
CREATE TABLE project (
  id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  name        VARCHAR(64) NOT NULL,
  api_key     VARCHAR(64) NOT NULL UNIQUE,   -- SDK 上报用，MVP 硬编码一个
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- Prompt 版本
CREATE TABLE prompt_version (
  id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  project_id  INT UNSIGNED NOT NULL,
  name        VARCHAR(64) NOT NULL,
  version     VARCHAR(32) NOT NULL,             -- v1.0 / v1.1
  content     TEXT NOT NULL,                    -- 含 {{input}} 占位
  description VARCHAR(255) DEFAULT '',
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_project_version (project_id, name, version)
);

-- 评测集
CREATE TABLE eval_dataset (
  id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  project_id  INT UNSIGNED NOT NULL,
  name        VARCHAR(64) NOT NULL,
  description VARCHAR(255) DEFAULT '',
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 评测 case
CREATE TABLE eval_case (
  id              INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  dataset_id      INT UNSIGNED NOT NULL,
  input           TEXT NOT NULL,
  expected_output TEXT DEFAULT '',
  scoring_criteria TEXT DEFAULT '',
  created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_dataset (dataset_id)
);

-- 评测运行（一次 A/B 对比）
CREATE TABLE eval_run (
  id                  INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  dataset_id          INT UNSIGNED NOT NULL,
  prompt_a_id         INT UNSIGNED NOT NULL,
  prompt_b_id         INT UNSIGNED NOT NULL,
  status              ENUM('running','done','failed') NOT NULL DEFAULT 'running',
  score_a_avg         DECIMAL(5,2) DEFAULT 0,
  score_b_avg         DECIMAL(5,2) DEFAULT 0,
  total_cases         INT DEFAULT 0,
  started_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  finished_at         DATETIME NULL,
  KEY idx_dataset (dataset_id)
);

-- 单 case 评测结果
CREATE TABLE eval_result (
  id              INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  run_id          INT UNSIGNED NOT NULL,
  case_id         INT UNSIGNED NOT NULL,
  score_a         DECIMAL(5,2) DEFAULT 0,
  score_b         DECIMAL(5,2) DEFAULT 0,
  judge_reason    TEXT DEFAULT '',
  created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_run_case (run_id, case_id)
);
```

### 4.2 ClickHouse（trace 明细）

```sql
CREATE TABLE trace_records (
  trace_id        String,
  project_id      UInt32,
  model           String,
  prompt_text     String CODEC(ZSTD(3)),
  output_text     String CODEC(ZSTD(3)),
  prompt_tokens   UInt32,
  completion_tokens UInt32,
  cost_usd        Float64,
  latency_ms      UInt32,
  source          String,           -- openai / deepseek / langchain
  status          String,           -- success / error
  error_message   String DEFAULT '',
  parent_span_id  String DEFAULT '', -- A3 嵌套 trace 预留
  created_time    DateTime
)
ENGINE = MergeTree
PARTITION BY toYYYYMMDD(created_time)
ORDER BY (project_id, created_time)
TTL created_time + INTERVAL 90 DAY;   -- MVP 不做冷存储，90 天后自动删
```

- 内存上限：`config.xml` 设 `max_memory_usage = 1073741824`（1G）。
- 100 万条约占 300MB（ZSTD 压缩后）。

## 5. 接口规范

### 5.1 统一返回

```json
{ "code": 0, "data": {}, "message": "ok" }
```

错误码：`400` 参数错误 / `401` 未授权 / `404` 不存在 / `422` 校验失败 / `500` 服务错。MVP 无登录，`401` 仅校验上报 `X-API-Key` 头。

### 5.2 核心接口清单

| 方法 | 路径 | 说明 | 对应指标 |
|---|---|---|---|
| POST | `/api/traces` | SDK 批量上报（body: TraceRecord[]） | M1/M2/M6 |
| GET | `/api/traces/{trace_id}` | 单 trace 查询 | 链路回放 |
| GET | `/api/metrics/summary?range=7d` | 看板聚合（按天分桶） | M3/M7 |
| GET | `/api/prompts` | Prompt 版本列表 | C2 |
| POST | `/api/prompts` | 新建版本 | C2 |
| GET | `/api/datasets` | 评测集列表 | C3 |
| POST | `/api/datasets` | 建评测集 | C3 |
| POST | `/api/datasets/{id}/cases` | 批量导入 case | C3 |
| POST | `/api/runs` | 启动 A/B 评测（body: dataset_id, prompt_a_id, prompt_b_id） | C6 |
| GET | `/api/runs/{id}` | 评测进度 + 结果 | C6 |

OpenAPI 文档：`/docs`（FastAPI 自动生成，第 6.5 步导出 openapi.json）。

## 6. 部署架构

### 6.1 docker-compose.yml（本项目 3 个容器）

```yaml
services:
  eoe-fastapi:
    build: 05_代码/backend
    ports: ["8086:8086"]
    environment:
      - MYSQL_HOST=host.docker.internal   # 共用 3310
      - CLICKHOUSE_HOST=eoe-clickhouse
      - REDIS_HOST=host.docker.internal  # 共用 6381
    depends_on: [eoe-clickhouse]

  eoe-clickhouse:
    image: clickhouse/clickhouse-server:24.8
    ports: ["8123:8123"]   # HTTP，宿主只映射 8123
    ulimits:
      nofile: 262144

  eoe-frontend:
    build: 05_代码/frontend    # build 后 nginx 或 vite preview
    ports: ["5179:5179"]
```

- **不编 MySQL / Redis**：复用共用基础设施（3310/6381），符合 R15「≤5 容器」。
- ClickHouse 内存 1G 上限通过 `command: clickhouse-server --max_memory_usage=1073741824`。

## 8. 技术风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| ClickHouse 100 万条聚合慢于 1s | M3 不达标 | 按天分区 + ORDER BY (project_id, created_time)；不达标降级 M3 到 10 万条写诚实边界 |
| 无真实 LLM API key | M4/M6/M7 judge 只能 mock | 开发期写 `LLMJudge` 接口，mock 实现返回固定分数；真实 key 留 `.env`，配了就切真实实现 |
| SDK 上报拖慢业务 | M1/M8 不达标 | aiohttp 异步 + 本地队列；上报失败 catch 全部异常；第 8 步用断网用例验证 |
| 16G 内存 OOM | 开发中断 | ClickHouse 限 1G、frontend 用 build preview 不用 dev server、Qdrant/RabbitMQ 已砍 |
| 成本核算不准 | M6 不达标 | 按 OpenAI/DeepSeek 公开定价表硬编码 `COST_TABLE = {"gpt-4o": {"input": 0.0025, "output": 0.01}, ...}`；单位 USD/1K tokens |
